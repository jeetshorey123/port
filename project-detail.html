AWS Call Transcription & Sentiment Analysis

Dockerized AWS Lambda pipeline that transcribes calls with Whisper, separates agent/customer speech, scores sentiment with VADER, detects compliance keywords, and stores results in DynamoDB.

Problem Statement

The central challenge is to process noisy customer-care recordings at scale while preserving speaker separation, sentiment context, and compliance signals for downstream reporting.

Multi-language Support
Hindi-English code switching makes single-pass transcription unreliable without multilingual ASR models.
Speaker Diarization
Agent and customer voices need to be separated before sentiment scoring is meaningful.
Compliance Tracking
Compliance teams require structured output schema rather than raw transcripts.

Methodology

Audio Ingestion
Uploaded MP3/WAV triggers the pipeline through S3 and invokes Lambda container.
Transcription
Whisper transcribes the file and diarization separates agent and customer streams.
Sentiment Analysis
VADER computes polarity scores while flagged keywords identify risky language.
Persistence
Structured JSON output stored in DynamoDB for audits, analytics, and monitoring.

Technologies Used

AWS Lambda
Serverless compute for scalable processing
Amazon S3

Whisper ASR
Multilingual transcription engine
VADER Sentiment
Social media sentiment analyzer
DynamoDB
NoSQL database for results

Containerization for Lambda

Implementation Details

The pipeline is architected as a fully serverless system leveraging AWS's managed services to ensure scalability, reliability, and cost efficiency. Each component is containerized using Docker for consistency across environments.

Key Features:

  • Automatic scaling based on queue depth
  • Real-time processing with <2min latency
  • Support for multiple audio formats
  • Granular compliance keyword matching
  • Full audit trail in DynamoDB
  • Integration-ready REST API
